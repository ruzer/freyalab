## Estado provisional

La prueba geométrica basal reprodujo el defecto: el diagrama alto sobresalía **1.003,88 px** por debajo del área útil. La ejecución focal final aprobó **12/12 casos en 15,3 s**. Se dejó **1 px de margen de seguridad** al descontar el relleno para evitar desbordamientos por redondeos fraccionales. No se usó `overflow:hidden`. La prueba final también comprueba el grosor de barras: **0×0 px** en ambos diagramas ajustados. Las cuatro capturas se sustituyeron por las de esa ejecución, conservando los originales y sus hashes en el registro de procedencia.

Una primera suite E2E completa terminó con **245/246**: una prueba antigua esperaba el literal `110%` tras acercar, incompatible con la escala proporcional nueva. Se adaptó para esperar el render estable y comprobar que el SVG realmente crece. La nueva suite completa final aprobó **246/246 en 9,0 min**, sin reintentos. El build separado final también completó con salida 0. La CI de las cuatro plataformas sigue pendiente y se registrará sobre el head del PR; no se deduce de las pruebas locales.

## Mediciones geométricas

Todas las medidas siguientes son píxeles CSS. El área útil excluye el relleno calculado del lienzo. `overflow` es la diferencia **entera** entre dimensiones de scroll y de cliente. La instrumentación adicional `scrollbar` calcula el espacio ocupado por las barras a partir de `offsetWidth/offsetHeight`, `clientWidth/clientHeight` y los bordes.

| Escenario | Área útil | SVG visible | Escala / barra | Excedente entero X/Y |
|---|---:|---:|---|---:|
| Alto, base tras Ajustar | 544×594 | 543,50×1597,88 | 120,78 % real / 100 % mostrado | 0 / 1004 |
| Alto, implementación final | 551×594 | 201,70×593 | 44,82 % / 44,8 % | 0 / 0 |
| Ancho, implementación final | 551×594 | 550×11,45 | 19,26 % / 19,3 % | 0 / 0 |
| Ancho, panel estrechado | 431×594 | 430×8,95 | 15,06 % / 15,1 % | 0 / 0 |
| Ancho, ventana 1280×800 | 367×494 | 366×7,63 | 12,82 % / 12,8 % | 0 / 0 |
| Zoom manual tras redimensionar | 431×587 | 439,20×9,15 | 15,38 % / 15,4 % | 8 / 0; ya no está en modo ajustado |
| Alto, botón 100 % | 544×594 | 450×1323 | 100 % / 100 % | 0 / 729; tamaño natural solicitado |
| 250 conexiones, 251 nodos | 551×594 | 4,76×593 | 2,83 % / 2,83 % | 0 / 0 |
| Geometría 1×1 simulada | 551×594 | 550×550 | 55.000 % / 55.000 % | 0 / 0 |
| Zoom de Chromium al 150 % | 311×294 | 99,66×293 | 22,15 % / 22,1 % | 0 / 0 |

En la versión final, todos los registros en modo ajustado tienen barras de **0×0 px**. En tamaño natural y zoom manual pueden aparecer barras cuando el dibujo supera el área: es el comportamiento solicitado en esos modos. El caso enorme demuestra un ajuste inferior al antiguo mínimo del 20 %. Encajar todo el dibujo no implica que sus etiquetas diminutas sean legibles sin acercar; el usuario conserva el zoom manual.

Los valores completos, las rutas originales y los SHA-256 están en [mer-008-metricas-2026-10-27.json](mer-008-metricas-2026-10-27.json). Se incluyen **31 registros**: dos de la base original, dos rojos de barras y 27 de la ejecución final sin barras. Los archivos cuyo nombre empieza por `2-final-basal-` pertenecen a la ejecución final, no a la versión basal; su fase queda identificada en el JSON. El registro conserva además los hashes de las capturas y del código de la ejecución sustituida.

## Decisiones, límites y lo no verificado

- Cada instancia comienza en modo ajustado. Al recrearse una pestaña vuelve a ajustarse y responde al tamaño actual. El zoom manual no se conserva entre recreaciones de pestaña; no se añadió estado global ni persistencia en disco.
- Los cambios de `viewBox`, geometría 1×1 y panel temporalmente oculto se probaron mediante mutaciones del DOM de test. No son ejemplos de fuentes Mermaid que produzcan por sí mismas esos valores.
- El zoom de Chromium al 150 % no acredita un cambio físico de resolución, escala o configuración de pantallas de macOS, Windows o Linux.
- La medida de scroll inicial redondeaba a enteros y omitía una pista de 7 px. Se amplió la prueba al grosor de barra y se verificó el arreglo con un margen de seguridad de 1 px, manteniendo el scroll disponible en los modos manual y natural.
- No se cambiaron la caché ni las exportaciones. Esta rama parte de main `7955b68`; no incorpora mediante fusión la historia independiente FL-MER-009 sobre colores de exportación.
- No se añadieron dependencias ni se modificaron `package.json` o el lockfile. No se publicaron versiones, no se actualizó la app instalada y no se fusionó la rama.
- No se verificó aún la CI de cuatro plataformas de esta rama. Las ejecuciones locales no prueban Windows/Linux, instaladores, firma, notarización ni la aplicación empaquetada.
