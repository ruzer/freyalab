# FL-MER-001 · Errores de Mermaid comprensibles

Fecha de la sesión: 2026-10-26. Rama: `codex/mer-001-errores-diagrama`. Base actualizada: `da7a002aeeecfbd90eada16bc0b18825946b35a1` (incluye FL-MD-001). Worktree independiente; el checkout del usuario y su `graphify-out/` permanecen intactos.

## Cambio comprobado

- Explicación pura en español, con título, pista accionable y ubicación cuando existe evidencia. `detail` conserva exactamente el mensaje recibido. Se reconocen tipo desconocido, fuente vacía, sintaxis, final incompleto, flechas/relaciones y cierres de corchetes/comillas.
- `.mmd` conserva el último SVG válido, con opacidad 0,45, `inert` y `aria-hidden`; el aviso indica expresamente que no es la versión actual. Sin SVG previo ofrece un ejemplo mínimo seleccionable mediante teclado. El texto del usuario no se reemplaza.
- El mensaje original comienza dentro de `<details>` cerrado. Los controles de zoom se deshabilitan durante el error. El aviso se superpone al dibujo para no cambiar su posición al corregir.
- Markdown prepara el resultado antes de mostrarlo: cada bloque inválido tiene título, pista, ubicación relativa al bloque y detalle plegado insertados con `textContent`. Los bloques válidos siguen renderizándose. Se descartan respuestas antiguas y callbacks de vistas destruidas.
- Región `status` persistente, `aria-live="polite"`, sin el detalle técnico. Cambiar únicamente el fragmento técnico sin cambiar la explicación no modifica la región anunciada (verificado con `MutationObserver`). Se conserva el debounce de 150 ms. No se limpia el aviso al comenzar cada pulsación.
- SVG y PNG usan `Diagram.exportSVG()`; PDF usa `exportHTML()`, que llama a `exportSVG()`. Las tres salidas se prueban ante error: aparece **Corrige el diagrama antes de exportar.**, no hay diálogo nuevo ni archivos generados y la fuente en disco permanece intacta. También se prueban exportación con render pendiente y cierre de la pestaña mientras espera.

Válido → inválido → corregido; igualdad exacta del SVG retenido; opacidad y bloqueo de interacción; exportaciones SVG/PNG/PDF; exportar antes de terminar el render; cerrar durante exportación SVG y HTML; primer error sin dibujo previo; fuente vacía/espacios; múltiples bloques Markdown, bloque válido y HTML técnico literal; anuncio estable en `.mmd` y Markdown; generaciones superpuestas; cambio de tema; teclado y atributos accesibles.

## Límites y hallazgos fuera de alcance

- Mermaid 12.2.0 puede devolver un SVG con **Maximum text size in diagram exceeded**. La única modificación de `render.ts` comprueba el límite configurado antes de renderizar, para no cachear ni exportar ese diagnóstico como SVG válido. Es conservadora: `source.length` cuenta comentarios y frontmatter en unidades UTF-16 (50 000 actualmente). Se conserva la fuente y se invita a dividirla. No cambia `initialize`, saneamiento ni configuración de seguridad; los demás errores tampoco se cachean.
- La línea es la que comunica Mermaid. Algunas fuentes flowchart incompletas de dos líneas producen **Parse error on line 3** por el tratamiento del final de entrada del parser. Se conserva ese número y se pide revisar también la anterior; no se inventa una ubicación exacta del carácter.
- Cambiar de tema durante un error conserva el SVG válido anterior con su tema original, explícitamente atenuado y no actual. No se recalcula ni se exporta como el diagrama actual.
- No se añaden plantillas para `.mmd` vacío (FL-MER-002), navegación a la línea ni confirmaciones de exportación Markdown (FL-MER-006). Exportar un Markdown con bloques inválidos conserva su explicación; esta tarea bloquea las tres exportaciones del diagrama individual.
- UX-10 y F06 quedan cubiertos **en su parte de errores**. No se reabrió la auditoría ni se modificaron sus documentos. No se cambiaron `App.svelte`, `Editor.svelte`, CSV, dependencias, IPC ni guardado/recuperación.
- La ejecución remota de CI y la ejecución empaquetada se distinguen de instalar la aplicación: no se probó instalación ni se actualizó la app del usuario; no hay fusión ni release.
